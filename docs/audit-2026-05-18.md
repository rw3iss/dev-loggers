# dev-loggers audit — 2026-05-18

## State of play

The library is small, dependency-free, and largely fit-for-purpose. It already has:

- A `LoggerRegistry` singleton with `Logger` / `PerformanceLogger` / `BufferedLogger` subtypes.
- A `LogModule` hook (`addLogModule`) — single-listener fanout via `console.log`.
- ANSI colorization + namespace formatting.
- A namespace-keyed enable/disable map exposed via `getLoggerStates` / `enableLogger` / `disableLogger`.

## Concrete problems found

| # | Where | Problem |
|---|-------|---------|
| 1 | `globals.ts` `emitLog` | Always calls `console.log(...)` regardless of whether any sink is attached or wants console output. Coupled to console. |
| 2 | `LogModule` | Single-purpose hook with `onLog(event)` — but the panel wants an `id`-keyed payload, not raw `args`. No structured event. |
| 3 | `LogEvent` | Carries only `{ namespace, args }`. No `id`, `level`, `timestamp`, `data`. Consumers (the panel) re-derive these. |
| 4 | `Logger.log` | Always takes `...args: any[]` — no canonical `id` slot the way the user asked for (`debug('id', obj)`). |
| 5 | OCP | Adding a new transport requires implementing `LogModule.onLog` with an event shape that lacks structure, then hand-parsing `args`. No "sink" abstraction. |
| 6 | DI | `Logger` and the global `log`/`warn`/`error` functions reach into the singleton registry directly. Hard to spin up an isolated logger for tests. |
| 7 | Performance | No short-circuit when a logger is disabled AND no modules are attached — still walks `formatNamespace`, builds args array. Cheap, but not free. |
| 8 | Naming | `LogModule` is vague (everything is a "module"). `Sink` is the standard term. |
| 9 | Composition | The factories (`getLogger`, `getPerformanceLogger`, `getBufferedLogger`) silently return a wrong-subtype logger if the same namespace was registered earlier with a different factory. No type check. |

## Improvements (this PR — v4)

- **Add canonical `debug(id, ...args)` global**, with an attached fluent variant: `debug.scope('audio:attach').log(...)`. Maps to `LogEvent.id`.
- **Introduce `Sink` interface** — `Sink.write(event: LogEvent)`. `LogModule` is now an alias of `Sink` for back-compat.
- **Built-in `ConsoleSink`**, attached by default. `attachSink(s)` / `detachSink(s)` to compose.
- **Richer `LogEvent`** — `{ id, namespace, level, args, timestamp, data? }`. `level` is `'log' | 'warn' | 'error' | 'debug'`. `data` is the first object arg (handy for panels).
- **Lazy emit** — if zero sinks are registered AND the namespace is disabled AND there is no override, the path now returns before allocating the event object.
- **Side-channel registry helper** — `createLoggerRegistry()` for tests / non-singleton setups. Globals continue to use the singleton.
- **Type-correct factories** — `getLogger('x')` returns the same instance only if it's the same subtype; otherwise the factory throws (loud is better than silent wrong-type).

## Migration delta (v3 → v4)

- `addLogModule(m)` still works; new code should use `attachSink(s)`.
- `LogEvent.args` still present; new `id`, `level`, `timestamp`, `data` fields are additive.
- `debug(...)` is new — no conflict with anything in v3.
- The keyboard shortcut on the panel is a separate concern (handled in dev-debug-panel v2).
